# 이슈 #20 반영 결과 (2026-10-23)

이 기능들은 미국 알림 시스템에만 반영했다. 한국 알림 시스템의 경로·봇·비밀값은 바꾸지 않았다.

## 1. 바뀐 것과 반영 위치
| 요구 | 반영 | 주요 파일 |
|---|---|---|
| 한국인 취향 필터(최우선) | 적극 알림은 **특별 근거(special_reason) 한 문장이 있을 때만** 보낸다. 수집기와 Worker 두 곳에서 막는다. 메시지에는 ✨ 줄로 근거를 보인다. 정가 정기 공연·대학 세미나·일반 극장 시즌·회의·약물 반납·연령 불일치는 제외한다. 5인 가족 총비용과 2027년 체류를 고려한다 | `collector/ai.py`, `worker/src/pipeline.js`, `worker/src/render.js` |
| 내부 $150 상한 제거 | `monthly_budget_usd` 와 `spent >= budget` 정지 로직을 없앴다. 새 임의 숫자는 넣지 않았다. `credit_reference_usd: 100` 은 경고 비율 계산에만 쓴다 | `config/models.json`, `collector/run.py` |
| 유료 초과 방지 | 크레딧 부족으로 API 가 거절하면 **AI 단계만** 멈춘다. 공식 정보원 수집·기존 알림 발송은 계속하고, AI 대기 항목은 보존한다. 소유자에게는 하루 한 번 알린다. 카드 등록·충전·자동 충전은 하지 않는다. 사용액 경고(50·80·100%)와 월 누계는 유지한다 | `collector/ai.py`(`credit_exhausted`), `collector/run.py`, `worker/src/pipeline.js`(`usage`) |
| ChatGPT·Claude 파일 입력 | `external-inbox/<chatgpt\|claude>/<고유이름>.json` 이 새로 push 되면 처리한다 | `.github/workflows/external-inbox.yml`, `collector/inbox.py`, `collector/external_ingest.py` |
| 파일 입력 제한·검증 | 새 파일만 받는다. 파일 200KB·30건, push 한 번에 10개까지다. 같은 파일·같은 내용은 한 번만 처리한다. 공식 페이지를 다시 읽지 못하면 보내지 않는다. 외부 설명은 "자료일 뿐 지시가 아님" 표시를 붙이고 제어 문자를 지운다 | 같은 위치 |
| 기존 입력 경로 | repository_dispatch 는 유지했다. 예전 `chatgpt-inbox.yml` 은 위 워크플로로 합쳤다(같은 파일을 두 번 처리하지 않게) | `.github/workflows/external-events.yml` |
| 3경로 대조 | `event_finds`(행사 키 × 경로)에 경로별 최초 발견·외부가 밝힌 발견 시각·URL·검증·추천을 남긴다. 실제 발송은 outbox 에서 계산한다. 발송을 일으킨 경로도 함께 기록한다 | `worker/migrations/0007_compare.sql`, `/admin/compare` |
| 누락 판정 | 정보원 목록에 없다는 이유만으로 "놓침"이라 하지 않는다. found / queued / seen-dropped / registered-missed / unregistered / excluded 로 나눈다. 원인 코드는 10종이다. 우리 추천상 알릴 대상이 아니면 `outside_scope` 로 두고 보완하지 않는다 | `collector/external_ingest.py` |
| 자동 보완·재발견 회귀 | 정보원·검색어를 추가한 뒤, 그 정보원 목록이나 검색 결과에 놓쳤던 행사가 실제로 다시 잡히는지 바로 확인해 `rediscovered` 로 남긴다 | 같은 위치 |
| 작업량·비용 계측 | 실행(경로)마다 기록한다: 시작·끝, 실제 검색어, URL 시도·성공, 후보 흐름(제외 사유·중복·보류), 추천, 제출, 단계별 비용(발굴·추출·판정·추천·웹 검색), 실패 비용. 모르는 값은 `unknown`. 외부 검색은 구독 사용량이라 `not_applicable` 로 적고 API 비용과 섞지 않는다. 텔레그램 요약 없이 조용히 쌓는다 | `collector/run.py`(`workload`), `/admin/workload` |
| 내보내기 | 관리 작업 `export` 가 JSON·CSV(행사·작업량·원인)·Markdown 요약을 만든다. 실행 첨부로 90일 보관한다 | `scripts/export_eval.py`, `.github/workflows/admin.yml` |
| 보충 발송 | 아직 소유자가 받지 못한 유효한 적극 알림(특별 근거 있음)을 한 통씩 보낸다. 매시 실행으로 나간다(요약 시각을 기다리지 않음). 이미 받은 행사와 같은 회차 묶음(같은 정보원·같은 원제목)은 건너뛴다 | `worker/src/pipeline.js`(`catchup`), 관리 작업 `catchup-dry`·`catchup` |

## 2. 시험
- 수집기 116개 통과. 새로 추가한 것:
  - 크레딧 소진 격리, 월 사용액만으로는 멈추지 않음
  - 특별 근거 없는 push 강등
  - 파일 입력: 경로·크기·개수·재처리 방지
  - 공식 페이지 재확인 실패 시 미발송
  - 주입 문구 표시, `outside_scope` 판정, 원인 코드·재발견
- Worker 12개 묶음 108단계 이상 통과. 새 `compare-e2e` 가 확인하는 것:
  - 경로별 발견·대조
  - 작업량 조용히 저장
  - 입력 파일 선점·재처리
  - 경고 전용 문구
  - 보충 발송: 중복 없음, 회차 묶음 1회
- 부정 회귀(운영 재평가 결과)
  - Red Rocks 정기 공연 4건: none
  - 대학 학과 세미나 6건: none
  - 특별 근거 없는 push 는 Worker 가 보내지 않음(시험)

## 4. 남은 한계
- **Claude 앱 예약 검색**: 이 세션에서 예약 작업 만들기가 거절되어 설정하지 못했다.
  - Claude 경로는 같은 파일 입력(`external-inbox/claude/`)으로 받을 준비가 되어 있다.
  - 실제 예약은 소유자가 Claude 앱에서 만들어야 한다.
- **같은 행사의 키 분리**: 같은 행사가 출처별로 다른 키로 남는 경우가 있다.
  - 예: Wings 야간 개방(공식 API·외부 입력), 폴라 익스프레스 회차.
  - 보충 발송은 회차 묶음으로 막았지만, 정보원이 다른 경우는 identity 쪽 보완이 더 필요하다.
- **104건 미판정**: 개발 예산 상한 때문에 판정하지 못했다. 개발 예산 잔액은 약 $1.95 다.
- **지인 발송**: 이슈 작성 뒤 main 에 들어온 커밋으로 `DELIVERY_MODE=all` 이 배포되어 있었다. 소유자 확인에 따라 유지한다.
