## 1. staging-test 안전성

| 지적 | 수정 |
|---|---|
| 고정 이름 `us-alert-db-staging` | 실행마다 `us-alert-worker-stg-<run_id>-<run_attempt>`, `us-alert-db-stg-<run_id>-<run_attempt>` |
| 이미 있는 DB 를 재사용한 뒤 무조건 삭제 | 같은 이름이 이미 있으면 **시작하지 않음**(재사용 경로 삭제). 정리는 이 실행이 만들려고 한 이름만, 만들기 직전에 남긴 표시(`D1_ATTEMPTED`, `WORKER_ATTEMPTED`)가 있을 때만 |
| 운영 자원 오삭제 위험 | Worker 삭제는 시험 이름이 적힌 시험 설정 파일 + `--name` 을 함께 지정할 때만. 설정 확인에 실패하면 자동 삭제하지 않고 오류로 남김. 원격 시험 스크립트는 `-stg-` 이름이 아니면 실행 거부 |
| 실패·중단 시 정리 | 정리 단계는 `if: always()` — 단계 실패·취소·단계 시간 초과에도 실행. 단계별 제한 합(약 30분) < 작업 제한 40분이라 작업 시간 초과에도 정리할 시간이 남음. 3회 재시도 후 실제로 사라졌는지 확인, 남으면 이름과 수동 삭제 명령을 오류로 표시 |
| 이전 실행이 남긴 것 | 지우지 않고 경고로만 알림 |
| 공유 무료 한도 | 시작 전 오늘(UTC) 계정 전체 사용량을 Cloudflare 분석 API 로 재고, 사용량 + 시험 예상이 한도의 80% 를 넘거나 **잴 수 없으면 시작하지 않음** |

| 항목 | 무료 한도/일 | 시험 예상 | 비고 |
|---|---|---|---|
| Workers 요청 | 100,000 (계정 공유) | 약 150 (여유 1,000 으로 점검) | 초과 시 오류 1027 |
| D1 쓴 행 | 100,000 | 약 1.8만 (2.5만으로 점검) | **2026-09-01 부터 초과 시 UTC 자정까지 계정의 모든 D1 쿼리 실패** — 한국 D1 포함 |
| D1 읽은 행 | 5,000,000 | 50만 이하로 점검 | 같음 |

## 2. 첫날 기준선 알림

| 지적 | 수정 |
|---|---|
| 기준선 중에도 '오늘 접수 시작'·'내일 마감'이 즉시 ⏰ 발송 | 기준선 중에는 시간 알림을 **일간 요약**으로 만든다(⏰ 표시 유지). 처리 기록은 남겨 기준선이 끝난 같은 날 즉시 알림으로 중복되지 않음 |
| main 병합 직후 첫 자동 수집이 기준선 설정보다 먼저 돌 수 있음 | ① 마이그레이션이 기준선을 **'시작 대기'** 상태로 심음. 운영자가 시작·해제하기 전까지 기준선으로 동작<br>② collect·dispatch 앞에 **준비 관문**: 배포된 Worker 가 기준선 상태를 갖췄을 때만 실행, 아니면(배포 전·중) 그 회차를 건너뜀 |

재현 시험(`worker/test/review4-e2e.mjs`):

| 시나리오 | 수정 전 | 수정 후 |
|---|---|---|
| 배포 직후(기준선 명령 전) 옛 행사 20건 + 가까운 행사 1건 수집 → 즉시 발송 0, 요약만 | **실패: 기준선 비활성** | 통과 |
| 기준선 중 오늘 접수 시작·내일 마감 → 즉시 0, 요약 1통에 둘 다 | **실패: 즉시 ⏰ 2건** | 통과 |
| 기준선 해제 후 같은 날 재실행 → 중복 즉시 알림 없음 | 통과 | 통과 |
| 기준선 해제 후 새 접수 기회 → 정상 즉시 ⏰ | 통과 | 통과 |
| 준비 관문: 준비된 Worker READY=1, 응답 없는 Worker READY=0 | (관문 없음) | 통과 |

남는 점:
- 기준선 중 시간 알림은 요약 시각(기본 오전 8시)에 나간다. 그날 요약이 이미 나갔다면 '내일 마감'은 다음 날(마감 당일) 아침 요약에 실린다.
- 운영자가 `baseline-start`/`stop` 을 하지 않으면 계속 기준선(조용한 등록 + 요약)으로 남는다. `admin` → `baseline` 에서 `awaiting_start` 로 확인할 수 있다.

## 3. 운영 시작 순서(확정)

1. main 병합 → `deploy-worker`: D1 0003 적용(기준선 '시작 대기') → 새 Worker 배포. 이 사이 예약 collect·dispatch 는 준비 관문에서 건너뜀.
2. 배포가 끝나면 자동 수집이 돌아도 기준선 대기 상태라 즉시·대량 발송 없음.
3. 소유자 전용 E2E: `test-send` → 버튼 → `clicks`.
4. `baseline-start`(36시간, 대기열이 크면 72시간까지) → 요약 확인 → 기간 만료 또는 `baseline-stop`.

## 4. 실제 D1 시험 준비 상태

| 확인 | 상태 |
|---|---|
| 시험 자원 고유 이름·자기 것만 정리·운영 자원 보호 | 완료(가짜 계정으로 단계 실행 시험) |
| 무료 한도 사전 점검(못 재면 중단) | 완료(판정 논리 시험). 실제 분석 API 호출은 첫 실행에서 확인 |
| 텔레그램 발송 불가(봇 토큰 없음, 닫힌 주소) | 유지 |
| 남은 위험 | ① Cloudflare 토큰에 분석 읽기 권한이 없으면 점검 단계에서 멈춤(안전한 실패) → 권한 추가 필요<br>② 실행기 자체가 강제 종료되면 정리 단계가 못 돌 수 있음 → 다음 실행이 경고로 알려 주고, 이름에 실행 ID 가 있어 수동 정리 대상이 명확<br>③ 시험 예상 쓴 행(1.8만)은 추정치. 실제 값은 첫 실행 뒤 분석 화면에서 확인 |
