## 원본 오류와 계정 상태의 한계

GitHub 연결 도구는 job 로그 다운로드를 지원하지 않는다. IAB/Chrome 모두 GitHub 비로그인 상태여서 원문 로그는 로그인 필요. 공개 요약만으로 원래 HTTP 상태코드/Anthropic error.type/원문 메시지를 복원할 수 없다. 기존 extract는 오류를 `credit-exhausted`로 축약하며 CREDIT.error를 report/run-log에 보내지 않았다. 따라서 로그인 후에도 해당 실행이 원문을 남기지 않았다면 당시 원인을 소급 확정할 수 없다.

확인된 코드 결함: `credit_exhausted()`가 APIStatusError 메시지에 `billing` 또는 `purchase credits`만 있어도 잔액 소진으로 판정했다. 일반 결제 문제를 잔액 부족으로 단정하는 오류다. 지출 한도·키 인증/권한 문제도 별도로 진단해야 한다.

[Anthropic 문서](https://platform.claude.com/docs/en/api/errors): 401 인증, 403 권한, 402 billing_error, 400 조직/워크스페이스 지출 한도 가능, 429 속도 제한 또는 사용 등급 지출 한도 가능. 크레딧 부족은 명시적 부족 메시지가 있어야 분류한다. HTTP만으로 잔액을 추정하지 않는다.

[Max 월 API 크레딧](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-ultra-and-team-plans)은 연결한 Console 조직에 지급되고 그 조직의 키들이 공유한다. 사용자가 알려준 월 $100/12월 6일 갱신은 존중하되, 현재 조직 잔액/키 소속/워크스페이스 한도는 직접 확인되지 않았다. 추가 결제·자동충전·한도 상향은 하지 않는다. models.list 성공은 인증 확인일 뿐 유료 Messages 호출 가능 여부의 충분한 증거가 아니다. 이번에는 이미 성공한 실제 수집 실행을 가용성 증거로 사용했다.

## 예약 지연은 별도 장애

cron은 full 12:30 UTC, light 00:40/04:40/08:40/16:40/20:40 UTC. 공개 요약의 지연은 각각 137/473/90분이다. 11/4 06:57 UTC → 16:33 UTC에는 실행 시작 간격이 9시간36분이었다. 11/2 06:46 → 18:48 UTC 간격은 약12시간이다. 최신 작업 생성은 22:10:25, job 시작은 22:10:36, 종료는 22:18:38 UTC로, 작업 생성 뒤 runner 대기는 11초였다. 장시간 AI 처리나 30분 timeout이 이 지연을 만든 것으로 보이지 않는다. 예약 trigger 생성 이전 지연이 관찰되지만 GitHub 내부 스케줄러의 정확한 지연/누락 원인은 공개 기록만으로 확정할 수 없다.

[GitHub schedule 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)는 높은 부하에서 지연/누락 가능성을 명시한다. 고정 시각 보장으로 취급하지 않는다. AI 결제 오류가 GitHub 예약을 멈춘다는 증거는 없다.

Worker에는 이미 Durable Object 매시 알람이 있다. GH_REPO는 미국 저장소로 설정되어 있으며 GH_DISPATCH_TOKEN이 있어야 collect.yml workflow_dispatch 요청이 가능하다. 사용자가 받은 no-token 경고는 당시 누락 증거이며 현재 secret 유무는 직접 조회하지 않았다. 토큰을 새로 만들거나 권한을 넓히지 않았다.

최소 설정 절차(운영 적용 승인 뒤):

1. fine-grained PAT의 repository access를 `hyuckkk/us-alert-collector` 한 곳으로 제한, repository **Actions: Read and write**만 부여(자동 Metadata read 외 불필요한 Contents/Administration 권한 추가 금지). [dispatch 권한 문서](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event).
2. 짧은 만료일을 정하고 기존 key_expiry 알림에 등록. 토큰 문자열은 채팅/코드/로그에 남기지 않는다.
3. GitHub Actions secret `GH_DISPATCH_TOKEN`과 미국 Worker secret을 일치시킨다. GitHub secret만 넣으면 이미 배포된 Worker는 즉시 갱신되지 않는다. 기존 deploy-worker가 비어 있지 않은 값을 동기화하지만 배포는 별도 승인 필요. 한국 Worker는 대상이 아니다.
4. `/admin/status`에서 새 bool 표시와 마지막 heartbeat/복구 결과만 확인. 실제 복구 dispatch 시험은 AI 사용·기존 정책에 따른 발송을 일으킬 수 있으므로 먼저 범위를 보고한다.

## 안전한 코드 변경

- Anthropic 오류를 credit-exhausted/billing/spend-limit/authentication/permission/rate-limit/provider-unavailable/connection/invalid-request로 구분. HTTP/type/정제된 메시지/request ID/발생 시각을 기록하며 key/header/request body는 수집하지 않는다.
- 계정 전체 차단은 그 실행의 추가 AI 호출을 중단하되 크레딧 소진 플래그와 구분. 해당 실패 항목의 임대만 해제해 개별 재시도 횟수가 소진되지 않도록 한다. 참가 자격·일상행사 제외·추천·중복 방지 기준은 유지한다.
- 수집 시작/종료/보고 수신, 실제 AI API 성공 응답 시각을 분리. 호출이 없거나 추정 비용만 기록한 경우 성공으로 취급하지 않는다. 부분 실패에서 복구를 선언하지 않는다. 오래된 보고/동일 보고가 건강 상태를 되돌리거나 복구 알림을 중복 생성하지 않는다.
- 월 사용액 참고금액을 실제 보유 잔액처럼 표현하지 않는다.
- 기존 Worker 복구 경로를 유지하며 6시간 rolling cooldown, timeout/403/네트워크 실패 기록, 잘못된 날짜 진단을 추가. AI 오류와 수집 지연 알림을 구분한다. 미병합 #45의 해당 안전장치만 재사용하며 달력/가입 UI 변경은 포함하지 않는다.
- Windows에서 로컬 Worker 검사가 가능한 test harness 보완. 실제 서비스에 보내지 않는 가짜 Telegram/GitHub와 로컬 D1만 사용.
