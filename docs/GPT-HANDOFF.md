# 콜로라도 행사 알림 — 개선 결과와 외부 검색 연동 안내 (ChatGPT 전달용)

작성 2026-10-22. 미국 알림 시스템(GitHub `hyuckkk/us-alert-collector`, Cloudflare Worker `us-alert-worker`, 텔레그램 봇 3개)의 현재 상태다.
최근 두 차례 소유자 지시의 결과를 정리하고, ChatGPT 가 찾은 행사를 같은 봇으로 보내는 방법을 담았다.

봇 세 개:
- 가족: @ColoradoFamily_bot
- 어린이: @ColoradoKids_bot
- 일상(성인): @ColoradoLife_bot

한국 알림 시스템(telegram-relay·한국 봇)과는 완전히 분리돼 있다. 지인 발송은 꺼져 있다(소유자 전용).

## 1. 이전 지시 결과 — 알림 형식·추천 품질·외부 연결

### 1-1. 알림 형식(실제 수신 화면 지적 반영)
| 이전 | 지금 |
|---|---|
| 한 메시지에 행사 10건씩 길게 나열 | **행사 1건 = 메시지 1통** |
| 본문에 `https://…` 전체 주소 | **본문에 주소 없음** → 메시지 아래 **[🔗 공식 안내]** 버튼이 공식 페이지로 연결 |
| 번호별 체크 버튼 수십 개 | 메시지마다 **[✅ 확인] [🚫 관심없음]** 두 개. "🔕 이런 종류 그만"은 관심없음을 누른 뒤에만 나타남 |
| '미확인' 줄 반복 | 확인된 정보만. 없는 항목은 줄째로 생략 |
| 영어 원문 그대로 | 간결한 한국어 제목, 날짜는 "11월 20일(금)"(콜로라도 현지 기준), 시간·비용·연령도 한국어 |

메시지 구성(위에서 아래로):
1. 제목(굵게)
2. 특징: 🏃 선착순 · 🆓 무료 · 📌 예약 필요 · 🎲 추첨 · 🗓 접수 예정 · ⏳ 마감 임박 · ✨ 특별 체험 · 🎫 허가 필요 · 🎉 연례 행사
3. 무엇을 하는 행사인지 한두 줄
4. 📅 날짜·시간 / 📍 장소 / 💲 비용 · 👤 대상 / 📝 신청 시작·마감 / 🛂 참가 조건

### 1-2. 추천 품질(일상 봇 60건 지적 반영)
- 원래 문제: 시의회 회의, 계획위원회, 약물 반납, 영유아 동화 시간, 시니어 프로그램이 성인 체험 알림으로 나갔다. 공식 일정표를 그대로 전달하는 수준이었다.
- **수집과 발송을 분리했다.** 수집은 줄이지 않고 모두 저장한다. 보내는 것은 아래 판정으로 고른다.
- **추천 판정 단계**: 추출 다음에 Opus 가 발송 후보 **전부**를 판단한다. 판정이 없으면 보내지 않는다.

  | 등급 | 뜻 | 발송 |
  |---|---|---|
  | 적극 알림 | 공연, 축제, 스포츠 관람·참여, 체험, 취미 강좌, 대학 공개 행사, 특별 시설, 국립·주립공원 허가·예약, 캠프·프로그램 접수, 선착순·추첨, 드문 경험 | 모두에게 |
  | 관심 설정 시 | 영유아, 시니어 전용, 도서관 정기 모임, 지지 모임, 틈새 강연 | `/interests` 로 그 분야를 고른 사람만 |
  | 일반 제외 | 시의회·위원회·공청회, 약물 반납·행정 서비스, 직원·회원 전용, 대상이 맞지 않는 것 | 그 분야를 직접 고른 사람만 |

  판정 항목: 대상 봇 재지정, 분야, 점수, 간결한 제목, 한두 줄 설명, 특징. 거리·가격만으로 빼지 않고, 특별한 경험일수록 높게 평가한다.
- **실제로 보냈던 일상 알림 60건 재평가**(표 전체: 저장소 `eval/life_sent_review.md`)
  - 적극 알림 20건: 성인 할로윈 야간 체험, 피클볼 대회, 몰입형 연극, 대학 아이스하키, 가이드 하이킹·지질 투어, 취미 강좌
  - 관심 설정 시 33건: 시니어 전용, 유아 스토리타임(어린이 봇으로 이동), 정기 북클럽·명상, 지지 모임
  - 일반 제외 7건: 시의회, 계획위원회, 환경자문위원회, 역사랜드마크위원회 회의, 약물 반납 2건, 법률 자문 클리닉
- **운영 DB 전체 재판정**: 304건 → 적극 207 · 관심 72 · 제외 25.

### 1-3. 외부 검색 결과 연결(ChatGPT → 봇)
- 경로: GitHub `repository_dispatch` → 워크플로 `external-events` → `collector/external_ingest.py` → 미국 Worker `/admin/enqueue`.
- 받은 내용을 그대로 믿지 않고 기존 수집과 같은 단계를 거친다.
  1. 주소·제목 검사
  2. 공식 페이지 재조회
  3. 추출
  4. 정밀 판정
  5. 추천 판정(Opus)
  6. 같은 행사 판별
- Worker 관리 키는 GitHub 비밀값에서 실행 중에만 만들고 출력하지 않는다.
- 메시지에 출처(GPT·ChatGPT 등)를 표시하지 않고, 형식·버튼·중복 방지·대기열이 다른 알림과 같다.
- 실제 시험: Denver Botanic Gardens "Blossoms of Light"(2026-11-20~2027-01-10)를 등록했고, 소유자에게 가족 봇으로 1통 발송했다.
- 같은 행사 재입력은 같은 키로 판별했다(새 행사 아님). 표현만 다른 재입력이 '변경'으로 잡히던 결함은 수정했다.

## 2. 이번 지시 결과

### 2-1. 하루 건수 제한 없음
- 하루 5건 제한을 없앴다. 추천된(적극 알림) 행사는 모두 한 통씩 보낸다.
- 텔레그램 호출 한도 때문에 한 번 실행에 25통까지 보내고, 나머지는 다음 매시 실행에서 이어 보낸다. 받는 사람마다 나눠 써서 한 사람 몫이 다른 사람 몫을 막지 않는다.
- 묶음 목록·번호 버튼 방식은 다시 나오지 않는다.

### 2-2. 비용
- 프로그램 자체의 월 AI 상한($150)은 **없앴다**(이슈 #20). 실제 한계는 소유자의 Anthropic API 선불 크레딧(Max 연동 월 $100, 카드 없음)이다.
- 크레딧이 바닥나 API 가 거절하면 AI 단계(발굴·추출·판정·추천)만 멈추고, 공식 정보원 수집·기존 알림 발송은 계속한다. 대기 항목은 보존하고 소유자에게 하루 한 번 알린다.
- 카드 등록·크레딧 구매·자동 충전·유료 초과 사용은 소유자 승인 없이 하지 않는다. 사용액 경고(크레딧 기준 50·80·100%)와 월 누계는 유지한다.
- 2027년 5월까지 토큰을 줄이는 변경(모델 낮추기, 판정 생략, 수집·발굴 축소)은 하지 않는다.

### 2-3. 외부(ChatGPT) 알림으로 놓친 검색 찾기 → 구조적 보완
ChatGPT 가 보낸 행사마다 "우리 수집이 이미 찾았는가"를 자동으로 대조한다.

| 판정 | 뜻 | 자동 조치 |
|---|---|---|
| found | 우리 정보원·검색이 이미 등록 | 없음(같은 행사로 합쳐 다시 알리지 않음) |
| queued | 수집은 했지만 AI 처리 전 | 기록. 처리 대기열이 밀린 것 |
| registered-missed | 등록된 기관 사이트인데 못 찾음 | Opus 가 원인 분석 → 그 사이트의 더 구체적인 목록 페이지(예: 특별 행사 페이지)를 정보원에 추가 + 검색어 추가 |
| unregistered | 그 기관이 정보원에 없음 | Opus 가 그 기관의 공식 행사·접수 페이지를 찾아 정보원에 추가 + 검색어 추가 |

- 공식 페이지는 GitHub 서버에서 **실제로 조회되는지 확인한 뒤에만** 정보원으로 추가한다.
- 검색어는 다음 날부터 매일 검색에 들어간다.
- 결과는 Worker 표 `ext_gaps` 에 쌓이고, 주간 보고에 "외부 검색 대조: 우리도 찾음 n · 놓침 n … (자동 보완)"으로 나온다.
- 이번 실제 대조 결과는 §3-3 에 있다.

## 3. ChatGPT 가 행사를 보내는 방법

### 3-0. 파일로 보내기(권장, 이슈 #20)
ChatGPT GitHub 연결의 파일 만들기(create_file)로 이 저장소에 **새 파일**을 만든다. push 되면 `external-inbox` 워크플로가 자동으로 처리한다.
- 경로: `external-inbox/chatgpt/<고유이름>.json` (Claude 예약 검색은 `external-inbox/claude/…`). 고유이름은 영문·숫자·`.`·`_`·`-`, 예: `2026-10-24T0700Z.json`.
- 새 파일만 처리한다. 같은 파일·같은 내용은 한 번만 처리한다. 파일은 200KB, 30건까지.
- 형식(스키마 `us-alert-inbox/1`). 모르는 값은 빼면 `unknown` 으로 기록된다.
```json
{
  "schema": "us-alert-inbox/1",
  "run": {"started_at": "2026-10-24T07:00:00Z", "finished_at": "2026-10-24T07:12:00Z", "searches": 14,
          "queries": ["Denver holiday lights tickets 2026"], "urls_attempted": 30, "urls_ok": 26, "official_pages_checked": 12,
          "candidates": 40, "excluded": 33, "excluded_reasons": {"past": 9, "routine": 20, "far": 4}},
  "events": [{"title": "...", "url": "https://기관 공식 페이지", "start_date": "2026-11-20", "end_date": null, "time": "...", "location": "...",
              "cost": "...", "age": "...", "registration_opens": null, "deadline": null, "description": "...", "audience": "family",
              "verified": true, "verification_note": "공식 페이지에서 날짜·가격 확인", "found_at": "2026-10-24T07:05:00Z", "origin": "scheduled",
              "recommend": "push", "special_reason": "한 문장: 왜 특별한가(드문 공개·기간 한정·선착순·공공 지원 대폭 할인 등)"}]
}
```
- 공식 페이지를 시스템이 다시 읽는다. 다시 읽지 못한 행사는 `verified: true` 라도 보내지 않는다.
- 메시지는 미국 봇 3개로 소유자에게만 간다. 행사 하나에 한 통이고, GPT·Claude·미국 같은 출처 표시는 붙지 않는다.
- 우리 수집기가 같은 행사를 먼저 찾았는지 3경로(GitHub 수집기·Claude·ChatGPT)로 대조해 조용히 쌓는다.
- 놓친 것은 원인 코드(missing_source, query_gap, scrape_or_js_failure 등)를 붙이고 정보원·검색어를 자동으로 보완한다. 보완 뒤 같은 행사가 다시 잡히는지도 확인한다.
- 키·토큰은 파일에 넣지 않는다.

### 3-1. 호출(repository_dispatch, 기존 방식 유지)
```
POST https://api.github.com/repos/hyuckkk/us-alert-collector/dispatches
Authorization: Bearer <GitHub 토큰>
Accept: application/vnd.github+json

{
  "event_type": "external-events",
  "client_payload": {
    "test": false,
    "events": [
      {
        "title": "Blossoms of Light at Denver Botanic Gardens",
        "url": "https://www.botanicgardens.org/events/special-events/blossoms-light",
        "start_date": "2026-11-20",
        "end_date": "2027-01-10",
        "time": "4:30-9 p.m. nightly (closed Nov 26, Dec 25)",
        "location": "Denver Botanic Gardens, York Street, Denver",
        "cost": "timed tickets online",
        "age": "all ages",
        "registration_opens": "2026-10-28",
        "deadline": null,
        "description": "Holiday light display; timed-entry tickets online only; weekends sell out.",
        "audience": "family"
      }
    ]
  }
}
```

- **필수**: `title`, `url`(https, 가능한 한 **기관 공식 페이지**. 티켓 재판매·뉴스 사이트보다 공식 페이지)
- **선택**: `start_date`·`end_date`·`registration_opens`·`deadline`(YYYY-MM-DD), `time`, `location`, `cost`, `age`, `description`(1,500자까지), `audience`(family | kids | life)
- 한 번에 30건까지. 넘는 것은 받지 않는다.
- `"test": true` 면 등록한 행사(최대 3건)를 소유자에게 바로 1통씩 보낸다(시험용).
- 대상 봇은 `audience` 를 참고만 하고, 추천 판정이 최종으로 정한다.
- 토큰: 이 저장소 하나만, 저장소 내용 쓰기 권한(repository_dispatch 호출용). 소유자가 직접 만들어 ChatGPT 쪽에만 둔다(저장소·로그에 남기지 않음).

### 3-2. 무엇을 찾아 보내면 좋은가(추천 기준과 같은 방향)
- 우선: 선착순·추첨·예약 시작일, 국립·주립공원 허가·시간지정 입장, 캠프·강습 접수 시작, 특별 체험, 드문 행사, 축제·공연, 대학 공개 행사.
- 반복 정기 프로그램, 행정 회의, 민원 서비스, 정가 일반 공연(Red Rocks 정기 공연 등), 대학 일반 세미나·콜로키엄·학제간 토론, 일반 극장·공연장 시즌, 일반 스포츠 경기는 보내지 않아도 된다(받아도 '특별 근거' 없이는 알리지 않는다).
- 보낼 때는 `special_reason` 에 왜 특별한지 한 문장을 적는다. 예: 평소 비공개인 군·항공·우주 시설 개방, 기간 한정, 선착순·추첨, 공공 지원 대폭 할인·무료 특별 프로그램. 5인 가족 총비용과 2027년 체류 기간을 함께 본다.
- 지역: 덴버 광역권(Westminster 중심). 특별한 경험이면 멀어도 된다(예: 로키산맥 국립공원 허가).
- 같은 행사를 다시 보내도 된다. 같은 행사로 판별해 다시 알리지 않는다. 날짜·비용 등 실제 값이 바뀌었으면 "🔄 변경"으로 한 번 알린다.

### 3-3. 이번 대조 결과(실제, 2026-10-22)
ChatGPT 가 찾을 만한 실제 행사 3건을 외부 경로로 넣어 대조했다(비용 0.07달러).

| 행사 | 대조 | 원인(Opus 분석) | 자동 조치 |
|---|---|---|---|
| Denver Botanic Gardens Blossoms of Light (11/20~1/10) | 등록 정보원인데 놓침 | 식물원 일반 행사 목록과 별도로 특별 행사 페이지가 있는데 그 목록을 감시하지 않음 | **정보원 추가**: botanicgardens.org/events/special-events. **검색어 추가**: "Blossoms of Light Denver tickets", "holiday light show Denver tickets", "Denver Botanic Gardens holiday lights" |
| Denver Zoo Zoo Lights (11/23~1/3) | 등록 정보원인데 놓침 | 연례 행사 전용 페이지로만 공지. 동물원 사이트가 GitHub 서버 접속을 막음(403) | 공식 페이지는 접속이 막혀 정보원 추가 불가. **검색어 3개 추가**("Zoo Lights Denver tickets" 등) → 매일 검색으로 보완 |
| 로키산맥 국립공원 시간지정 입장 | 행사로 등록하지 않음 | 2027년 일정이 아직 공지되지 않아 날짜가 없음 | 이미 그 공식 페이지를 변경 감시 중. 2027년 일정이 올라오면 접수 시작일 알림 |

이 과정에서 드러난 결함 두 가지는 바로 고쳤다.
1. 같은 행사가 표현만 달라도 '변경'으로 잡힘 → 숫자·핵심 값으로 비교
2. 이번 입력에 없는 정보가 기존 값을 지워 '변경'으로 잡힘 → 기존 값 유지

잘못 생긴 변경 알림 2건은 발송 전에 취소했다.

## 4. 검증(자동 시험)
- 각 메시지의 [🔗 공식 안내]·[✅ 확인]·[🚫 관심없음] 버튼이 그 행사에 정확히 연결된다.
- 아주 긴 행사도 한 통 4,096자 이하다. 잘린 행사가 발송 완료로 기록되지 않는다.
- 실패한 통은 그 행사만 다음 실행에서 다시 보낸다(폭주·중복 없음).
- 접수 시작 ⏰ 알림은 빠지지 않는다.
- 재평가로 제외된 행사는 보내기 직전에 다시 걸러진다.
- 시의회 회의·약물 반납·관심 미설정 영유아 행사·판정 없는 행사는 기본 발송되지 않는다.
- 한 사람의 많은 요약이 다른 사람 몫을 막지 않는다(사람별로 나눠 발송).
- 외부 행사 대조 4분류, 조회되는 공식 페이지만 정보원으로 추가, 검색어 추가.
