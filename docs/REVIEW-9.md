## 1. 개인정보 이력 정리(A안 유지)

| 지시 | 반영 |
|---|---|
| 옛↔새 커밋 대응표를 공개 저장소에 두지 않음 | REVIEW-8 의 대응표·첫 변경 지점·브랜치 끝 해시를 지웠다. 개인정보가 든 옛 커밋을 가리키던 커밋 번호(REVIEW-3·4)도 "비공개"로 바꿨다. 대응표는 `history_rewrite_check.sh` 가 **비공개 출력 폴더에만** 만든다 |

## 4. 전체 수집 성능 시험(준비만 — 유료, 승인 후 실행)

- 실행: `stage4-preop` 에서 `ticks/fullsystem` push(선택: `max=N`). Worker·텔레그램에는 쓰지 않는다(건식).
  1. `run.py --mode full --dry-run --max 1500 --trace reports/fullsystem-trace.json` — 일반 수집 + 키워드 검색 + AI 신규 발굴(Opus, 3분야 + 요일 심층) + AI 추출(Haiku) + 애매한 건 AI 판정(Opus)
  2. `eval_stages.py` → `eval/stages.json`
- 기준 행사별 측정 항목:

| 항목 | 내용 |
|---|---|
| 발견 단계 | 등록 정보원 / 키워드 검색 / AI 발굴 중 어디서 잡혔나(여러 곳 가능, "그 단계에서만" 수도 집계) |
| AI 처리 | 추출 성공·실패 사유, 행사로 남았는지(관련 없음 판정·지난 행사 제거 포함) |
| 정확도 | 날짜(접수 시작 정보는 접수일), 비용(무료 여부·금액), 연령 조건 — 원문 기준과 비교 |
| 알림 대상 | 지인 기준(지금부터) / 소유자 기준(비밀값의 참가 가능일을 주면 계산) — 즉시·요약·예고·아님 |
| 오탐 | 제외 13건(지난·전용·확인 불가)이 알림 대상이 되면 오류로 집계 |

- 비용 추정: AI 발굴·판정(Opus) 약 $2–4 + 추출(Haiku, 항목 약 1,200) 약 $0.4 → **약 $3–6**(이전 건식 실행 실측 기준).
  - 건식 실행은 Worker 의 월 사용액을 모르므로 `--max` 로 상한을 둔다.
  - API 콘솔 사용액에는 반영된다.
  - 월 예산 $20 안에서 가능하나, 이번 달 시험 누적과 함께 판단이 필요하다.
- 제약:
  - 알림 대상 계산은 Worker 규칙을 단순화했다(기준선 미반영).
  - 키워드 검색 단계는 제목 유사도로만 대조한다.
- 시험 코드: `collector/tests/test_eval_stages.py` 2건(단계 귀속·정확도·알림·오탐 집계, `--trace` 기록) 통과.
